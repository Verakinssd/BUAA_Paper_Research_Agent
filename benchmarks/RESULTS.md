# 实验结果（2026-10-27，RTX 5090）

按 `EXPERIMENTS.md` 的方案跑完的第一轮结果。

> **更新（2026-10-27 晚）：** 实验期间 PR #2 和 PR #3 还未合并，所以下面是它们各自的分支相对 `baseline` 标签（`095efbd`，合并前）的对比。之后管理员在集成 PR #5 中解决了二者的冲突并一并合入 main（默认均关闭），**本报告没有测试合并后的 main**。结论对 main 的含义见各节末尾。
原始数据在 `benchmarks/baselines/` 和 `benchmarks/results/`，相关性标签在 `benchmarks/rank_labels.jsonl`。

**一句话结论**

- **基线（E0）**：Q4 模型在单张 RTX 5090 上跑完 100 条查询，全部成功，平均每条 111 s，总计 3.1 小时。
- **并发（PR #2，E1）**：分阶段并发相对当前的“整篇并发 2”**没有可检出的提速**（平均差 -1.3 s，区间含 0，小于噪声）。“并发 2”本身比串行快约 12%。
- **排序（PR #3，E2）**：精排没有带来可检出的提升。池子排序层面，8 组配对共 64 项指标里只有 2 项显著，而且是**变差**；任务 Agent 选出的 Top-k 层面，精排的排序本身无可检出影响，但它默认让任务 Agent 只看前 8 篇，这一截取使选出的 Top-k 相关性**显著下降**（平均相关度 2.69 → 2.56）。
- 以上排序结论基于**大模型打的标签，尚未经过人工抽查**，见“局限”。

## E2 排序与 Top-k 相关性（PR #3）

标签：864 对（论文，想法）由同一个大模型打 0–3 分，其中 68% 为相关（≥2 分），41% 为最高分。20 个想法，按想法配对做 bootstrap。

### 候选池排序质量（不含任务 Agent）

| 配置 | nDCG@5 | P@3 | recall@8 |
|---|---|---|---|
| 每源 8 篇（生产设置），第一阶段 basic | 0.705 | 0.767 | 0.590 |
| 同上，bm25 | 0.736 | 0.733 | 0.571 |
| 同上，bm25 + PR #3 精排 | 0.735 | 0.733 | 0.583 |
| 每源 25 篇，basic | 0.619 | 0.783 | 0.208 |
| 同上，basic + 精排前 16 篇（默认） | 0.591 | 0.683 | 0.204 |
| 每源 25 篇，bm25 | 0.642 | 0.750 | 0.194 |
| 同上，bm25 + 精排前 16 篇（默认） | 0.646 | 0.717 | 0.192 |
| 同上，bm25 + 精排全部候选 | 0.684 | 0.733 | 0.206 |

共比较了 8 组配对（basic 与 bm25 互比、PR #3 各配置对基线），每组 8 项指标，**只有 2 项的 95% 区间排除 0**，且都是变差：25 篇池里在 `basic` 排序上做默认精排（只重排前 16 篇），P@3 从 0.783 降到 0.683（区间 [-0.183, -0.017]），P@5 从 0.800 降到 0.710（区间 [-0.170, -0.020]）。64 项检验里出现 2 项边缘显著不排除偶然，应当谨慎看待。

“25 篇池里精排全部候选”是最有利的情形：nDCG@5 相对 basic 高 0.065（区间 [-0.015, +0.148]）、相对 bm25 高 0.042（区间 [-0.025, +0.111]），都没有达到显著。basic 与 bm25 两种已有排序之间同样没有可检出的差异，说明 20 个想法的评测集只能检出较大的差异。

### 任务 Agent 选出的 Top-k（每源 8 篇，k=1..5）

| 配置 | 平均相关度 | 精确率 | nDCG |
|---|---|---|---|
| 基线 basic | 2.670 | 0.966 | 0.948 |
| 基线 bm25 | 2.695 | 0.982 | 0.956 |
| bm25 + PR #3（默认，任务 Agent 看前 8 篇） | 2.560 | 0.915 | 0.866 |
| basic + PR #3（默认） | 2.593 | 0.925 | 0.895 |
| 对照：bm25，不精排，只看前 8 篇 | 2.598 | 0.925 | 0.901 |
| 对照：bm25 + 精排，任务 Agent 看全部 16 篇 | 2.686 | 0.969 | 0.951 |

配对差值（相对基线 bm25）：

| 比较 | 平均相关度差 | 95% 区间 |
|---|---|---|
| PR #3 默认 | -0.135 | [-0.222, -0.052]，**不含 0** |
| 只截取前 8 篇（不精排） | -0.097 | [-0.185, -0.024]，**不含 0** |
| 精排但任务 Agent 看全部 16 篇 | -0.008 | [-0.046, +0.026]，含 0 |

**解读：** 伤害来自 `RERANKER_AGENT_TOP_M=8` 的截取，不是精排的排序。池子里相关论文前 8 的召回率只有约 57%，截掉的部分任务 Agent 就选不到了。让任务 Agent 看全部候选时，PR #3 与基线没有可检出的差异，也就没有收益。基线任务 Agent 的 Top-k 精确率已经是 0.98，最终 Top-k 层面几乎没有提升空间。

## E1 并发（PR #2）

端到端运行，真实主 Agent、真实下载与转换、全新 PDF 缓存；检索结果冻结，各版本候选完全相同。8 条查询 x 2 轮 x 4 个版本，同一查询的各版本背靠背、顺序随机。

| 版本 | 成功率 | 均值 | 相对基线的配对差 | 95% 区间 |
|---|---|---|---|---|
| base-concurrent（基线：整篇并发 2） | 0.625 | 73.5 s | — | — |
| base-control（与基线完全相同，测噪声） | 0.625 | 71.7 s | -1.9 s | [-4.1, +0.6] |
| base-serial（串行） | 0.625 | 80.6 s | **+7.1 s** | [+1.1, +12.7] |
| pr2-staged（`PIPELINE_MODE=staged`） | 0.625 | 72.2 s | -1.3 s | [-3.6, +0.7] |

- 噪声基线 1.9 s：分阶段并发的 -1.3 s **没有超过噪声**，结论是“没有可检出的提速”。
- 串行比并发 2 慢，且随 top_k 增大差距变大（k=2 慢 9 s，k=3 慢 14 s，k=4 慢 18 s），说明“同时处理两篇论文”是有效的；分阶段调度在此之上没有额外收益。
- 云机器网络很快（arXiv 约 17 MB/s），瓶颈在大模型摘要。PR #2 主要优化的是下载和转换，在慢网络下才可能显现，这次**不能证明**它在慢网络下无效。
- 只有 10 个有效配对（k=1 占 4 个，k=5 一个都没有）：任务成功率 0.625，失败全部是任务 Agent 选中了没有公开 PDF 的论文（或 PDF 超过 20 MB），各版本同样失败，所以成对丢弃。

## 其他发现

1. **真实检索会漏掉 arXiv。** arXiv 检索使用精确短语匹配（`all:"..."`），主 Agent 的大模型写出多词检索词时 arXiv 常常返回 0 篇，系统退化成只有 OpenAlex。这使得直接用真实检索做 A/B 不可靠，E1 因此用冻结候选。这本身也是一个可以改进的点。
2. **任务成功率受“没有公开 PDF”限制。** 任务 Agent 在筛选时不知道论文能否下载，k 越大越容易失败。
3. **相关性标签偏宽松**（68% 为相关），候选池来自关键词检索本来就偏相关；评测的区分力有限。

## 局限与未完成

- **标签未经人工抽查。** 打标签的模型和被评测的任务 Agent 是同一个模型，可能偏向自己的选择。已导出 60 条抽查表（`rank_sample.csv`，不在仓库里），人工填完后标签哈希会变，排序评测需要重跑（几秒钟；Top-k 选择评测约 10 分钟一组）。
- 只有 20 个想法，置信区间较宽。
- 一块 GPU、一台机器的结果；E0 只代表该硬件。
- 实验时 PR #2 与 PR #3 在 `research/pipeline.py` 冲突，所以没有做两者叠加的实验；二者之后已在 PR #5 合入 main，叠加后的行为没有测过。
- 精排（`PAPER_RERANKING_METHOD`）和分阶段并发（`PIPELINE_MODE`）在 main 上默认关闭，所以眼下不影响线上；但谁开启精排，就会遇到上面的“只给任务 Agent 看前 8 篇”问题（`RERANKER_AGENT_TOP_M` 默认 8）。
- 数据源优化（E3）没有实现。
